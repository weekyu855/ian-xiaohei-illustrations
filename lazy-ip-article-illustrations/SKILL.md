# 慵懒男生 IP｜六格文章配图

## 核心目标

把文章中的关键判断、流程、冲突、因果关系或隐喻，转化为**一张完整的 6 格拼版画布**。默认一次图像生成，不逐格分别生图。每格表达一个独立认知锚点，网格清晰，方便后期裁切。

风格方法参考 Ian Xiaohei Illustrations 的文章配图工作流，但角色必须使用用户自己的慵懒男生 IP。借鉴的是文章理解、角色参与动作、原创隐喻、留白和手绘编辑插画方法，不复制上游具体角色或既有案例构图。

## 必须先读取的参考

按需读取以下文件：
- `references/style-dna.md`：画风、线条、颜色和留白。
- `references/personal-ip.md`：固定人物外观。
- `references/composition-patterns.md`：六格叙事结构和隐喻设计。
- `references/prompt-template.md`：一次性六格生图模板。
- `references/qa-checklist.md`：生成前后质量检查。
- `assets/references/`：用户提供的人物设定图和配图风格参考，只用于角色和画风校准，不照搬具体画面。

## 参考图必须实际进入生图请求（硬性要求）

仅仅把图片放在仓库里，或在提示词里写“参考图片”，不代表图像模型真的看到了图片。每次生图前都必须执行以下流程：

1. **读取并确认素材存在**，使用仓库内的实际文件，不用搜索到的相似图替代：
   - `assets/references/character-sheet.png`：个人 IP 主参考，锁定脸型、发型、半眯眼、胡茬、服装与头身比例。
   - `assets/references/character-poses.png`：个人 IP 辅助参考，锁定正面、侧面、背面及不同姿态下的角色一致性。
   - `assets/references/article-style-reference.png`：画风与文章配图参考，锁定线条、灰阶、留白、场景叙事及少量橙黄色点缀。
2. **把原始图片作为图像输入，实际附加到本次图像生成调用中**。不要只把路径或文件名写进文本提示词。
3. 若生图工具/运行环境支持多张参考图：三张都传入，并在提示词中说明各自职责。若只支持一张参考图，优先传 `character-sheet.png`，并将 `article-style-reference.png` 的风格规范写进提示词；如果支持两张，则传角色设定图和文章风格图。
4. 如果当前执行环境无法把仓库图片附加到图像生成请求，**必须明确告知用户需要上传/附加参考图，不能声称已经使用了图片参考，也不能静默退化为纯文字生图**。
5. 不要把参考图中的旧场景、旧文字、数字或具体故事复制到新图中。只提取人物身份与视觉语言，场景内容必须来自当前文章。
6. 生图提示词必须有“参考图优先级”：人物身份以角色设定图为准；画风以文章配图参考为准；当前文章只决定每格的场景和隐喻。

生图调用前的自检：
- [ ] 参考图文件确实存在且已读取/选定。
- [ ] 图像文件作为视觉输入附加到生图请求，而不仅是写入提示词。
- [ ] 提示词明确区分“角色参考”和“画风参考”。
- [ ] 若无法附加图片，已如实说明限制。

## 工作流

### 1. 阅读与提炼文章

使用用户提供的正文、文件或可读取链接。提炼：
- 一句话核心论点；
- 3–6 个关键判断或因果环节；
- 文章中的事实、数字、比较关系、时间与限定条件；
- 主要冲突、反直觉之处和结论；
- 哪些概念最适合转成角色动作或视觉隐喻。

不得编造事实或改变文章中的数字、单位、因果关系。如果链接无法读取，坦诚说明并请求正文。

### 2. 规划恰好 6 格

默认布局：横向画布、3 列 × 2 行。每格独立、有均匀留白分隔和裁切安全边距。若文章明显更适合竖版，仍保留 6 格，可使用 2 列 × 3 行，但必须是一张画布。

推荐叙事：
1. **问题／钩子**：主角面对核心问题。
2. **背景／现状**：用场景或物件建立上下文。
3. **关键机制**：用动作、对比或隐喻解释核心逻辑。
4. **冲突／代价**：呈现限制、风险或矛盾。
5. **转折／方案**：角色采取行动、比较选项或重新思考。
6. **结论／记忆点**：用清晰视觉动作收束观点。

按文章实际逻辑调整顺序可以，但必须恰好 6 格，每格传达不同信息，不要重复凑数。

### 3. 让个人 IP 参与每格

主角不能只是六次站姿展示。让他做文章所需的动作：拆解、搬运、观察、对照、修补、推拉、筛选、记录、卡住、搭桥、做决定等。每格只选择 1–2 个主要物件；动作必须帮助读者理解观点。

### 4. 一次性生成整版

生图前先执行“参考图必须实际进入生图请求”协议；不得仅依赖文字描述来声称复现参考图。

用户要求直接生成时，不等待分镜确认。先简短给出核心论点与六格分镜，然后只调用一次图像生成，产出一张完整整版图。

必须在提示词中强调：
- 画面只有一张，内含恰好 6 个独立格子；
- 默认 3 列 × 2 行，网格和留白清楚、间距均匀；分格仅用自然留白，不做编号卡片；
- 每格可独立裁剪，人物、道具、文字不跨格；
- 角色在六格中保持同一外观；
- 统一白底、黑色手绘线条、灰阶铺色和少量橙黄色点缀；
- **禁止总标题、每格标题、序号、圆形数字徽章、页眉、图例、说明段落、装饰 Logo 和水印**；这是一张正文插画拼版，不是信息图海报；
- 不把六格合并成一个跨格的连续场景；
- 不生成六张分离图片，不要输出拼版之外的额外图像。

### 5. 文字与数据

- 图像以视觉表达为主，标签尽量短。
- 允许少量有意义的手写中文短句，参考原版技能中的编辑插画：通常在 2–3 格放置短句，其余格子纯视觉叙事。每处约 4–12 个汉字，整张图最多 3 处；文字必须补充观点，而不是复述画面。
- 禁止总标题、分格标题、序号、数字徽章、页眉、图例和说明段落。文字应像自然的手写批注，可配一笔橙黄色下划线；不能做成信息图海报。
- 不要放整段正文、复杂表格或密集说明。
- 重要数字要优先通过简单图形关系表现，并在分镜说明中单独列出，以便后续人工核对。
- 如果模型不能稳定绘制中文，提示其为标签预留干净空间，不用乱码填满；如必须保证文字准确，应在图中只保留少量短句，后续人工排字。

### 6. 交付

生成前的文字输出：
1. 核心论点（一句话）；
2. 六格分镜（每格一句，留在聊天文本中，不放进图片）；
3. 只安排 2–3 处短中文手写批注，其余格子不放字；禁止标题和序号；
4. 明确说明接下来只生成一张六格画布。

生成后说明整版已完成，并指出可按网格裁切。除非确实执行了裁切，不要声称已输出 6 个单独文件。

## 默认参数

- 格数：6
- 布局：3 列 × 2 行
- 画布：横向 3:2 或 16:9；若六格细节较多，优先 3:2
- 背景：纯白或接近纯白，不用复古纸纹
- 主色：黑、炭灰、中灰、白
- 强调色：橙黄／暖黄色
- 画风：黑色手绘线稿、轻微抖动的笔触、灰阶铅笔／马克笔质感
- 文案：极少量短标签
- 生图次数：一次
